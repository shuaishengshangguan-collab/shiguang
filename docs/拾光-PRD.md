## 一、产品概述

### 1.1 产品背景与目标

约拍（预约摄影师进行写真、旅拍、跟拍、婚礼纪实等拍摄）是一个需求真实存在、但长期缺少标准化交易基础设施的品类。当前交易大量发生在地域性的垂直约拍平台、内容社区的私信、以及闲鱼、小红书等泛交易与内容平台中。

对**摄影师**而言：客源依赖私域与熟人转介，接单不稳定；作品缺少稳定曝光渠道；交易无保障，常遇爽约、压价、尾款纠纷；定价缺乏参照。

对**需求方**而言：找人的路径长，需要在多个平台间比价、比作品；摄影师水平与报价不透明，选择成本高；最担心的是先付定金后被放鸽子，或成品不符合预期而缺乏追责手段。

对**市场整体**而言：撮合渠道分散，缺少"撮合 + 交易保障 + 信任评价"一体化的平台。

拾光的产品目标由此确定：

1. 让摄影师能够**持续、稳定、有保障**地靠拍摄赚钱；
2. 让需求方能够**快速、放心**地找到合适的摄影师；
3. 平台通过撮合服务费与增值服务获得收入，形成"摄影师多 → 供给足 → 用户多 → 订单多 → 摄影师收入高 → 吸引更多摄影师"的双边飞轮。

### 1.2 产品定位

拾光是一个**摄影师双边撮合交易平台**，平台内存在三类角色：需求方（个人或商家）、供给侧（摄影师与创作者）、平台方（运营与风控）。

核心差异化定位为：

> **强撮合 + 强保障 + 信任评价闭环**

其中"强保障"由四项机制构成——资金托管、爽约赔付、实名认证、双向评价。这四项不是并列的功能点，而是一条完整链路：认证解决"这个人可不可信"，托管解决"钱安不安全"，赔付解决"出事了怎么办"，评价解决"下次还选不选他"。四者缺一，交易的信任成本就无法真正下降。

### 1.3 本期范围（V1.0）

**V1.0 覆盖**：

| 端 | 范围 |
|---|---|
| 用户端 | 注册登录、首页信息流、搜索与筛选、摄影师主页、预约下单与支付、在线沟通、订单中心、评价、钱包、收藏与关注 |
| 摄影师端 | 入驻与认证、作品管理、服务套餐管理、排期管理、接单管理、收入中心、数据看板 |
| 平台端 | 审核、交易与资金托管、结算与佣金、风控与纠纷、内容与运营 |

**V1.0 明确不做**：视频与直播、机构批量托管账号、履约保险、智能推荐算法、跨城市多供给调度。上述能力统一放入 V1.x / V2.0 规划，目的是把首版收敛到一条能跑通的交易闭环上。

### 1.4 名词解释

| 名词 | 说明 |
|---|---|
| 资金托管 | 需求方支付的订单款项由平台冻结保管，服务经确认验收后再结算给摄影师；验收前平台为双方兜底 |
| 撮合服务费 | 订单结算时平台按约定比例（V1.0 为 10%）收取的服务费用 |
| 爽约赔付 | 任一方未按约定履约时，按规则从违约方保证金或托管款中赔付守约方 |
| 认证摄影师 | 通过平台实名与资质审核、获得认证标识的摄影师，享有更高曝光权重 |
| 套餐 | 摄影师发布的可直接下单的标准化服务单元，包含内容、时长、价格与适用范围 |
| 排期 | 摄影师设置的可约时间与忙闲状态，用于避免重复接单冲突 |

## 二、用户与角色

### 2.1 角色定义

| 角色 | 核心诉求 | 关键权限 |
|---|---|---|
| 需求方（个人） | 找到水平可见、价格透明、不放鸽子的摄影师 | 浏览、搜索、下单支付、沟通、确认验收、评价、申请售后 |

| 平台风控 | 处理资金安全与交易纠纷 | 资金冻结与解冻、仲裁裁定、账号处置 |

## 三、核心业务流程

### 3.1 下单—履约—结算主流程

| 步骤 | 角色动作 | 订单状态 | 资金状态 |
|---|---|---|---|
| 1 | 需求方浏览作品与摄影师主页 | —（尚未生成订单） | — |
| 2 | 选择套餐，约定时间与地点 | 待付款 | — |
| 3 | 提交订单并支付 | 待接单 | 托管冻结 |
| 4 | 摄影师接单；拒单则自动原路退款 | 待服务 / 已退款 | 冻结 / 退回 |
| 5 | 按约定时间地点完成拍摄 | 服务中 | 冻结 |
| 6 | 需求方确认验收或发起售后 | 待结算 / 售后中 | 冻结 |
| 7 | 平台扣除撮合服务费后结算给摄影师 | 已结算 | 解冻并分账 |
| 8 | 双方互评，订单关闭 | 已完成 | — |

关键规则：

1. 步骤 3 支付成功后款项即进入托管，摄影师在接单前无法动用；
2. 步骤 4 摄影师拒单不产生违约金，但拒单率计入其推荐权重；
3. 步骤 6 若需求方在约定时限内未操作，系统默认自动验收（默认 72 小时，可在后台按城市或套餐类型配置）；
4. 步骤 7 结算金额 = 订单金额 ×（1 − 10%）。

### 3.2 摄影师入驻认证流程

提交资料 → 实名认证 → 上传资质与作品 → 平台审核 → 审核通过获得认证标识并开张（驳回可补充材料重新提交）→ 发布作品与套餐 → 开始接单。

规则：未通过认证的账号可浏览与收藏，但**不可发布套餐、不可接单**。审核中状态对用户可见，避免出现"看起来能约、实际约不了"的体验断点。

### 3.3 售后与纠纷流程

需求方申请退款或投诉 → 平台介入 → 事实核对与责任判定 → 按裁定执行（全额退回 / 部分结算 / 全额结算）→ 结果留档并计入双方信用记录。

判定类型至少覆盖：摄影师爽约、需求方爽约、成品质量不符、服务内容与套餐描述不一致。

## 五、非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 核心页面首屏加载小于 3 秒；下单与支付接口 P99 小于 1 秒；支持万人级并发浏览 |
| 安全 | 实名认证；支付走合规支付通道，平台不得自设资金池；敏感信息加密存储与脱敏展示 |
| 合规 | 摄影师资质与作品内容合规审核；交易与退款规则明示；隐私政策与用户协议完整 |
| 可用性 | 支付与结算链路具备幂等设计，避免重复扣款或重复结算 |
| 可扩展 | 模块化架构，支持后续接入商家端、保险与推荐能力 |

## 六、数据埋点与指标体系

### 6.1 指标体系

| 维度 | 指标 |
|---|---|
| 供给侧 | 摄影师入驻数、作品发布数、接单率、拒单率、订单转化率、月均收入、提现频次 |
| 需求侧 | MAU、搜索到浏览转化率、下单支付转化率、订单完成率、复购率、好评率 |
| 平台 | GMV、撮合服务费收入、双边撮合成功率、爽约率、纠纷率 |

**北极星指标建议**：周成交订单数。理由是它同时反映双边供需的真实匹配程度，且与平台收入直接挂钩；相比之下 GMV 易被单笔高价订单干扰，MAU 无法反映撮合质量。

**核心漏斗**：曝光 → 咨询 → 下单 → 验收 → 复购。V1.0 需重点监控"咨询→下单"这一环，它是撮合效率最直接的体现。

## 八、风险与应对

| 编号 | 风险 | 应对措施 | 影响面 |
|---|---|---|---|
| R1 | 双边冷启动：单城市认证摄影师少于 50 人时，供给不足导致需求流失，需求流失又反过来抑制供给进入 | 以单城市单品类（毕业季写真）切入，先做深再做宽；对早期供给给流量倾斜与免佣期 | 影响增长节奏，不影响产品结构 |
| R2 | 跳单：双方交换私域联系方式后绕过平台私下成交 | 以托管保障的不可逆价值与评价沉淀锁定留存；对完单率显著低于均值的账号降权 | 影响抽佣收入 |
| R3 | 资金合规：平台自建收款账户形成资金池 | 分账与结算全部由持牌支付机构完成，平台只下发指令与对账 | 影响上线资质 |
| R4 | 定价带偏离主流接受区间：下单转化率低于 3%，且成交集中于最低价套餐 | 设置 299 / 399 / 499 三档价格带，保留调价空间 | 影响定价策略 |
| R5 | 保障机制被当作额外成本：保障服务开通率低于 30% | 将保障并入默认成交路径，不设为独立付费项 | 影响商业模式 |
| R6 | 供给侧接受度不足：摄影师侧月流失率高于 15% | 改为阶梯抽佣，月流水越高费率越低 | 影响供给侧规模 |
| R7 | 托管概念理解成本偏高：下单页停留时长显著偏高，退出集中在支付前一步 | 下单页以单行文案说明「确认收货后款项才结算给摄影师」，并以进度条呈现资金所处状态 | 影响支付转化 |
| R8 | 认证标签信任强度不足：摄影师主页到下单的转化低于 8% | 引入作品实拍验证与线下面谈，补充「最近 30 天成交」等实时信号 | 影响决策效率 |

风险应对的优先顺序：R1 与 R3 属于前置条件，未解决时其余风险不具讨论意义；R4 至 R6 属商业参数，可通过配置调整；R7 与 R8 属体验层，已在原型迭代中给出对应设计。
